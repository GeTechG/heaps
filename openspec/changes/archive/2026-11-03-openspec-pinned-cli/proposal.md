## Why
Nothing pins or checks OpenSpec here: agents used whatever global `openspec` they found, the repository has no OpenSpec skills (so all 21 archived changes were written by hand and none has `.openspec.yaml`), and CI never validates `openspec/` — `openspec validate --all --strict` of the current CLI (1.16.0) reports 15 over-long requirements across 11 main specs.

## What Changes
- `openspec/cli.pin` names the one OpenSpec CLI version this repository uses (`1.16.0`).
- The OpenSpec skills (propose, explore, continue, apply, update, ff, sync, archive, bulk-archive, verify) are generated by that version for Claude Code (`.claude/skills/openspec-*`) and Codex (`.agents/skills/openspec-*`) and committed.
- A new CI job, `openspec`, runs `openspec/check.sh` with the pinned CLI: strict validation of every spec and active change, no `TBD` Purpose, `.openspec.yaml` on every active change, skills generated by the pinned version, no unticked non-`[human]` task in the archive.
- `openspec/config.yaml` gains `rules.specs`, `rules.tasks` and `operations.apply` / `operations.archive` guidance that points at the steps in `AGENTS.md`.
- `.claude/skills/` and `.agents/skills/` become infrastructure paths: they do not exist upstream.
- The 15 over-long requirements are rewritten without changing behaviour: one behaviour in the text, the details in scenarios or separate requirements.
- `AGENTS.md` records the pin, how to bump it and how to run the check locally.

## Capabilities

### New Capabilities
- `openspec-workflow`: the pinned OpenSpec CLI, the skills it generates, and the CI check that keeps `openspec/` valid.

### Modified Capabilities
None. The rewritten requirements keep their behaviour; `commit-kinds` already defines infrastructure as whatever `.github/infra-paths` lists.

## Impact
Infrastructure only: `openspec/`, `.claude/skills/`, `.agents/skills/`, `.github/infra-paths`, `openspec/check.sh`, `.github/workflows/ci.yml`, `AGENTS.md`. No library code changes. Archived changes are not repaired; new changes are created only with `openspec new change`.
