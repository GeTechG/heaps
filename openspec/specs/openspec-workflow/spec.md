# openspec-workflow Specification

## Purpose
Every OpenSpec artifact of this repository is written and checked with one pinned OpenSpec CLI, through the skills it generates, and CI keeps `openspec/` valid on every push.

## Requirements

### Requirement: The OpenSpec CLI version is pinned
`openspec/cli.pin` SHALL hold exactly one line, a `MAJOR.MINOR.PATCH` version of `@fission-ai/openspec`, and every OpenSpec check of this repository SHALL run that version.

#### Scenario: CI runs the pinned version
- **WHEN** the `openspec` CI job runs
- **THEN** it runs `@fission-ai/openspec` at the version in `openspec/cli.pin`, whatever else is installed

#### Scenario: Malformed pin
- **WHEN** `openspec/cli.pin` is not a single `MAJOR.MINOR.PATCH` line
- **THEN** the check fails before running any validation

#### Scenario: Bumping the version
- **WHEN** the OpenSpec version has to change
- **THEN** one commit edits `openspec/cli.pin` and regenerates the skills with the new version

### Requirement: The OpenSpec skills are generated by the pinned version
The repository SHALL commit the OpenSpec skills propose, explore, continue, apply, update, ff, sync, archive, bulk-archive and verify for Claude Code under `.claude/skills/openspec-*` and for Codex under `.agents/skills/openspec-*`, each generated by the pinned CLI; the check SHALL fail when a skill's `generatedBy` differs from `openspec/cli.pin`.

#### Scenario: Skill from another version
- **WHEN** `.claude/skills/openspec-explore/SKILL.md` says `generatedBy: "1.13.2"` and the pin is `1.16.0`
- **THEN** the check fails and names that file

#### Scenario: Skills match the pin
- **WHEN** every `openspec-*` skill in both directories says the pinned version
- **THEN** this part of the check passes

### Requirement: CI validates specs and active changes strictly
CI SHALL fail when `openspec validate --all --strict` of the pinned CLI reports any issue, warnings included.

#### Scenario: Over-long requirement
- **WHEN** a main spec has a requirement whose text is longer than 500 characters
- **THEN** the `openspec` CI job fails

#### Scenario: Valid tree
- **WHEN** every spec and active change validates strictly
- **THEN** this part of the check passes

### Requirement: Main specs have a real Purpose
CI SHALL fail when the Purpose of a main spec under `openspec/specs/` starts with `TBD - created by archiving change`.

#### Scenario: Placeholder Purpose left by archiving
- **WHEN** archiving a change created `openspec/specs/foo/spec.md` and its Purpose is still the `TBD` placeholder
- **THEN** the check fails and names that spec

### Requirement: Active changes are created by the CLI
Every active change directory under `openspec/changes/` other than `archive/` SHALL contain `.openspec.yaml`, and CI SHALL fail when one does not.

#### Scenario: Hand-made change
- **WHEN** `openspec/changes/foo/` has a proposal but no `.openspec.yaml`
- **THEN** the check fails and names the change

#### Scenario: Archived changes are not checked
- **WHEN** an archived change under `openspec/changes/archive/` has no `.openspec.yaml`
- **THEN** this part of the check passes

### Requirement: Archived changes leave only human tasks open
CI SHALL fail when a `tasks.md` of an archived change has an unticked task (`- [ ]`) not marked `[human]`.

#### Scenario: Forgotten agent task
- **WHEN** an archived `tasks.md` has `- [ ] 2.1 add the test`
- **THEN** the check fails and names the file and line

#### Scenario: Open human task
- **WHEN** the only unticked task is `- [ ] 2.3 [human] try it with a real IME`
- **THEN** this part of the check passes
