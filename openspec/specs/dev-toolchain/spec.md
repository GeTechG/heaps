# dev-toolchain Specification

## Purpose
Every checkout builds, type-checks and navigates the sources with one compiler pinned in the repository, provisioned by one command.

## Requirements

### Requirement: The compiler is pinned in the repository
`tools/haxe-build.pin` SHALL hold exactly one line, `<build key> <sha256>`: the build key is 40 lowercase hex digits naming the file `haxe-linux64-<build key>.tar.gz` in the `builds` release of `GeTechG/haxe`, and the sha256 is the 64 lowercase hex digits of that archive. Building, type-checking and running tests SHALL use only this compiler.

#### Scenario: Changing the compiler
- **WHEN** the compiler has to change
- **THEN** the change is one commit that edits `tools/haxe-build.pin`, and re-running the setup switches the checkout to the new build

#### Scenario: Malformed pin
- **WHEN** `tools/haxe-build.pin` is not `<40 hex> <64 hex>`
- **THEN** the setup fails before downloading anything

### Requirement: One command provisions a checkout
`bash tools/setup.sh` SHALL, in a fresh checkout or worktree, install the pinned compiler into a per-user cache shared by all checkouts (one directory per build key), link it as the git-ignored `.haxe`, and make the libraries `all.hxml` names resolvable at commits pinned in the script, so that `PATH="$PWD/tools:$PATH" HAXE_STD_PATH=.haxe/std .haxe/haxe all.hxml` builds. The cache directory names SHALL NOT name any consumer of this library.

#### Scenario: Fresh worktree
- **WHEN** the setup has run once in a fresh worktree
- **THEN** `.haxe/haxe --version` reports the pinned build and `all.hxml` builds with it

#### Scenario: Checksum mismatch
- **WHEN** the downloaded archive does not match the pinned sha256
- **THEN** the setup fails, nothing is installed and `.haxe` is left as it was

#### Scenario: Build already installed
- **WHEN** the cache already holds the pinned build
- **THEN** the setup downloads nothing and only links it

### Requirement: The setup configures Serena's Haxe language server
The setup SHALL build `vshaxe/haxe-language-server` from its pinned commit into the per-user cache and write the git-ignored `.serena/project.local.yml` so that Serena starts that server with `.haxe` first on `PATH`. It SHALL create a minimal `.serena/project.yml` first when none exists, and SHALL NOT overwrite a `project.local.yml` that holds settings and lacks the generator's mark.

#### Scenario: Server reaches the compiler over a socket
- **WHEN** Serena starts in a provisioned checkout
- **THEN** the language-server log shows `Using --server-connect` and `find_referencing_symbols` on a source symbol returns references

#### Scenario: Foreign local configuration
- **WHEN** `.serena/project.local.yml` holds settings and no generator mark
- **THEN** the setup fails and leaves the file untouched

### Requirement: The display config names every module
The generated `.serena/lsp.hxml` SHALL be `all.hxml`'s HashLink/SDL build with libraries flattened to `-cp`/`-D` (no `-lib`, no `--macro`) and SHALL list, one dot-path per line, every module `all.hxml` includes (no `import.hx`). The list SHALL be generated by walking the source directories. The setup SHALL fail when the config does not compile.

#### Scenario: Config compiles
- **WHEN** the setup has run
- **THEN** `.haxe/haxe .serena/lsp.hxml --no-output` exits with code 0

#### Scenario: New source file
- **WHEN** a source file is added and the setup is re-run
- **THEN** its module appears in `.serena/lsp.hxml`

### Requirement: CI builds with the pinned compiler
The fork's own workflow `.github/workflows/ci.yml` SHALL, on every push to a branch (not on tag pushes), provision the checkout with `bash tools/setup.sh` and build `all.hxml` with the compiler it links as `.haxe`. The job SHALL fail when the setup or the build fails. The upstream workflow `.github/workflows/main.yml` builds with upstream's compilers and SHALL NOT be relied on as this check.

#### Scenario: Tree does not build with the pinned compiler
- **WHEN** a pushed commit does not build `all.hxml` with the pinned compiler
- **THEN** the run of `ci.yml` for that commit fails

#### Scenario: Toolchain cache hit
- **WHEN** the workflow cache holds a toolchain saved for the current `tools/haxe-build.pin` and `tools/setup.sh`
- **THEN** the job restores it and the setup downloads no compiler
